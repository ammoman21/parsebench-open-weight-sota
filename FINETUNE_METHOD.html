Teaching a document parser where bold lives

Why we fine-tune, what exactly we train, and how each design choice traces to a measurement

1The problem, in one paragraph

The best open-weight document parser on ParseBench outputs plain text: across 23,802 output elements it emits zero inline formatting — no bold, strikethrough, superscript or subscript — because its prompts never ask for any. The benchmark's formatting dimension scores exactly those markers. And 63.3% of the failed bold checks are text merged inside longer lines: the characters exist in the output but nothing separates them, so no post-processing script can ever find and wrap them. Only the model, at the moment it reads the image, knows what was bold. The fix must happen inside generation.

2Why not just ask? Because we measured that first

The obvious cheap fix is prompting: add "preserve bold as **text**" to the instruction. We ran that experiment four ways before training anything, and it produced the finding that dictates the entire training design:

Two facts fall out. The model can write the syntax — 1,729 markers on request — but it marks the wrong things, so the score falls as compliance rises. And bold degrades monotonically with how much the prompt was changed, even when the change asked for less: this 1.2-billion-parameter specialist is keyed so tightly to its training prompt that any perturbation damages its core behaviour. Knowing where bold belongs is judgment, and judgment is what fine-tuning installs and prompting cannot.

3What we actually train: a LoRA adapter

We do not retrain the model. LoRA (low-rank adaptation) freezes all 1.2B original weights and learns small correction matrices — about 24M parameters, 2% of the model — that are added to the attention and feed-forward layers at run time. Intuition: the model is a finished machine; LoRA installs small trim tabs on the control surfaces rather than rebuilding the engine. Three reasons it fits here: the change we want is a narrow output behaviour, not new knowledge; small adapters disturb existing behaviour least (and §2 proved this model punishes disturbance); and a run costs 15 minutes and ~$0.70, so we can iterate many times inside one night's budget.

4Every design choice, traced to the measurement that forced it

  • Train on region crops, not pages — because the pipeline's text stage never sees a page: a layout stage crops each region first and sends the crop. We traced this in its source. Training on the deployment distribution, not an idealised one.
  • The prompt in every training example is the production string, byte for byte ("\nText Recognition:\n") — because §2 showed any prompt change costs 2–5 points before training even starts. We change what the model does with its existing trigger, never the trigger.
  • Vision layers frozen — the model's localisation is its strongest sub-metric (0.869); perception was never the problem. Freezing it protects the Tables score (85.8) from collateral damage and halves what can go wrong.
  • Loss on the answer tokens only — the prompt is masked out of training so the model is never taught to generate its own instructions, only better answers to them.
  • ~30% of examples contain no styling at all, with plain-text targets — because §2's failure mode was indiscriminate marking. Negatives are how a model learns restraint; without them we would burn the "mark everything" failure into the weights permanently.
  • Synthetic data rendered from markup we control — pages are generated as HTML with known bold runs, superscript footnote marks, struck-through clauses, then rendered to images. The target markdown is therefore exact by construction, not annotated by a human or inferred by a bigger model. Using the benchmark's own annotations would be training on the test; distilling from a larger model would inherit its errors.
  • Only scorer-accepted spellings in targets (**bold**, ~~strike~~, <sup>/<sub>) and deliberately no underline or italic — we verified by executing the scorer that those two are annotated but counted in no score. Teaching them would add noise for zero points.
  • Insurance-flavoured content — the corpus this transfers to is majority rate filings in its table section; lexical and visual similarity is part of transfer.

5Why the training loop is 90 lines we wrote ourselves

The first three attempts used the standard framework (LLaMA-Factory) and all three produced NaN — "not a number", the state a computation enters after dividing by zero or overflowing, which poisons every weight it touches. Gradients were NaN from the tenth step in every configuration, including the textbook fixes. The decisive experiment cost two minutes: a bare forward pass through the model with plain transformers was numerically clean in both precisions. So the checkpoint was fine and the framework's training path was breaking it — this is a custom 1.2B variant the framework evidently mishandles.

The principle

When a black box misbehaves and the night is finite, replace it with the smallest system you can fully verify. Our loop is ~90 lines: load, encode exactly as production encodes, mask the prompt, step the optimiser, and assert the loss is finite at every step — it halts loudly rather than logging zeros over a corpse, which is precisely how the framework hid its own failure.

6The evaluation harness around the loop

Each iteration is judged in minutes, not hours: a fixed 40-document slice of the formatting dimension scores in ~2 minutes for ~10¢, and a second 30-document slice of the faithfulness dimension acts as a tripwire — a model taught to emit markup can start hallucinating it, and any faithfulness drop beyond 0.3 points disqualifies the checkpoint regardless of formatting gains. Full-corpus runs (~70 min, ~$3) are reserved for checkpoints that clear a pre-registered bar (70 on the subset). Decisions between iterations follow a written decision tree agreed before the night started, so 3am choices follow rules, not mood.

The signature matters more than the size: prompting traded bold away to gain superscript; training raised both at once, with targeted emission (37 bold markers across 40 documents, versus the prompt's 1,729 spray) and an untouched tripwire. That is what installed judgment looks like, and it is the difference between the two interventions.

8Honest limits

  • Subset scores are iteration signals, not corpus results; the 66.52 is comparable only to the 60.35 measured the same way. The pre-registered full-corpus run is what counts.
  • Rough transfer arithmetic puts formatting gains at roughly +1.2 overall — reaching ~76.0 against the leader's published 76.36. At the line, not past it. The chart dimension is the second lever being prepared.
  • Synthetic pages are cleaner than real scans; some gap between our rendered training data and the benchmark's messy documents is expected and unmeasured until the full run.
  • The base model is another team's work (KoreaDeepLearning, AGPL). What we publish is an adapter and method on top of it, attributed as such.

One sentence. Measurement showed the capability existed but the judgment didn't, and that the model punishes prompt changes — so we install the judgment directly in the weights, with the production prompt untouched, negatives to teach restraint, a self-verifying 90-line loop after the framework lied to us, and a tripwire so the cure can't be worse than the disease.
