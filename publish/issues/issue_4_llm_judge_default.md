# Chart evaluation defaults to a Claude-Haiku LLM normalization pass unless LLAMACLOUD_BENCH_LLM_NORMALIZATION=off — README says evaluation is deterministic, and two docstrings say the default is off

## What

The chart evaluation path includes an LLM-as-judge normalizer (Claude Haiku) that is **enabled by default**: the mode function returns `JUDGE` whenever the controlling environment variable is unset or unrecognized. This contradicts the README, and the codebase disagrees with itself about the default.

## Where

- `src/parse_bench/evaluation/metrics/parse/llm_normalization/config.py:34-42` — `get_normalization_mode()` reads `LLAMACLOUD_BENCH_LLM_NORMALIZATION` and "Returns NormalizationMode.JUDGE if unset or unrecognized."
- `config.py:17` — `JUDGE_MODEL = "claude-haiku-4-5-20251001"`.
- `src/parse_bench/evaluation/evaluators/parse.py:21-22` — the evaluator imports `RuleBasedJudgeMetric as RuleBasedMetric`, so the judge-capable class is the one every default run uses; `maybe_apply_llm_normalization` then post-processes failed chart rules (`chart_data_point`, `chart_data_array_labels`) via Anthropic API calls.

## The contradictions

1. `README.md:236`: "ParseBench does **not** use LLM-as-a-judge — all evaluation is deterministic and rule-based. API keys are only used to call the parsing tool being evaluated."
2. `rule_based_judge_metric.py:9` and `llm_normalization/postprocess.py:9` both document the env var as "(off by default)".
3. `llm_normalization/__init__.py:6-8` documents `"judge"` as the default — which matches what the code actually does.

## Evidence from a real run

Running the evaluation in an environment without the `anthropic` package installed surfaced `ModuleNotFoundError: No module named 'anthropic'` from `llm_normalization/strategy_judge.py:21` during chart scoring — confirming the judge path is active by default. (It degrades gracefully: initialization failure logs a warning and skips normalization.)

To be fair about scope: as far as we traced, the judge results are appended as parallel `_judge` metrics (`rule_pass_rate_judge`, `rule_*_judge_pass_rate`) rather than replacing the deterministic headline `rule_pass_rate`. The concern is not that published Chart numbers are LLM-derived — we could not establish that — but that the default behavior and the documentation point in opposite directions.

## Impact

- A default-configured run with `ANTHROPIC_API_KEY` in the environment makes third-party API calls during *evaluation*, with cost and run-to-run nondeterminism the README explicitly disclaims.
- Judge metrics generated by default sit next to the deterministic ones and are easy to confuse with the headline, especially for anyone comparing report JSONs across runs configured differently.
- Reproducers (like us) must discover an undocumented env var to get the behavior the README describes. We ran with `LLAMACLOUD_BENCH_LLM_NORMALIZATION=off` and declared it in our preregistration; our charts then reproduced your published numbers within 0.28.

## Suggested fix

Default the mode to `OFF` so the code matches the README and the two "(off by default)" docstrings — or, if judge-by-default is intended, update the README and docstrings, document the env var, and emit a prominent log line whenever judge mode is active. Either way, one of the three sources should stop being wrong.
